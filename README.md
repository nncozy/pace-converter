# ペース相互換算計算機（Pace Converter）

ランナー向けのペース相互換算Webアプリです。いずれかの距離のタイムを入力すると、
同じペースで走った場合の他の距離のタイムが瞬時に自動計算され、画面上のすべての
入力欄に同期されます。

## 対応距離（初期値）

50m, 200m, 400m, 800m, 1000m, 1500m, 3000m, 5000m, 10000m

左上の編集ボタンから、任意の距離の追加・表示/非表示の切り替えができます（後述）。

## 画面構成

HTMLファイルは1枚のまま、ハッシュ（`#training` / `#help`）で画面を切り替えています。
ファイルを分けなかったのは、Service Workerのプリキャッシュ対象と `?v=N` の同期先が
画面の数だけ増えて事故りやすくなること、テーマ確定のインラインスクリプトを全ファイルに
複製することになること、そして画面をまたぐと入力中のペースが消えてしまうためです。

| 画面 | 開き方 | 中身 |
|---|---|---|
| **換算**（メイン） | 既定 | ペース入力と距離カードの一覧 |
| **トレーニングペース** | ペース欄の下のボタン → `#training` | レース結果の入力＋VDOT。その下が2タブ（**練習ペース** / **ポテンシャルタイム**） |
| **使い方** | 一覧の下の「使い方」→ `#help` | 入力ルール・カード操作・VDOTの読み方など |
| 距離を追加・編集 | ヘッダーの ≡ → `#distances` | メイン画面に重ねるシート |

- 常設のタブバーは置いていません。換算画面が利用のほとんどを占めるので、
  残りのために全画面から高さを恒久的に削るのは割に合わないためです
- 端末の戻るジェスチャ・ブラウザの戻る・ヘッダーの ←・Escape は、すべて同じ「1つ戻る」に
  そろえています。URLを共有した相手が直接サブ画面を開いた場合は、相手の履歴を消費せずに
  換算画面へ戻します
- サブ画面から戻ると、換算画面は見ていたスクロール位置に戻ります

## 使い方

1. 好きな距離のタイム欄にタイムを入力する
2. 他のすべての距離の欄が自動的に同じペースのタイムへ書き換わる（書き換わった欄は一瞬だけ光ります）
3. 各欄に2桁入力すると自動で右隣の欄にフォーカスが移動する
4. 空の欄で Backspace を押すと左隣の欄にフォーカスが戻る
5. 画面上部の「クリア」ボタンで全欄をクリアできる（入力があるときだけ表示されます）

未入力の欄は `00` として計算されます。

### 入力欄は距離に合わせて出し分けます

全距離に `時 : 分 : 秒 . ms` の4欄を常設すると、50mの「時」やフルマラソンの「ms」のように
まず0以外にならない欄がタップ目標の間に挟まり、押しにくく読みにくくなります。そのため
距離ごとに必要な桁だけを出しています。

| 距離 | 既定で出る欄 |
|---|---|
| 3,000m 以下 | `分 : 秒 . ms` |
| 5,000m 以上 | `時 : 分 : 秒` |
| その間（3,001〜4,999m） | `分 : 秒` |

畳んである欄も、計算結果や入力で0以外の値が入った時点で自動的に現れます（値があるのに
隠れることはありません）。「時」を5,000mから常設しているのは、5kmを1時間超で歩く場合に
「分」の上限59分で詰まらないようにするためです。

### 入力元のカードが分かるようにしています

いま基準になっている距離のカードには「基準」バッジと強調枠が付きます。入力後に
すべてのカードが同じ見た目になり、どれが自分の入力でどれが計算結果か分からなくなるのを
防ぐためのものです。上部のペース欄に直接入力した場合は、どのカードにも付きません。

### ペースから決まる値をまとめて表示します

ペースが決まると、ペース欄のすぐ下に「400m 1周」「1マイル」「時速」を表示します。
ランナーが頭の中でやる換算を先回りするためのもので、入力はできません。

### 距離カードのスワイプ操作（非表示 / ピン留め）

LINEのトーク一覧と同じ感覚で、距離カードを横にスワイプするだけで整理できます。

- **左へスワイプ** → 「非表示」。少しだけスワイプするとボタンが出たまま留まるのでタップして実行、
  そのまま大きく払い切ればその場で実行されます
- **右へスワイプ** → 「ピン留め / ピン解除」。ピン留めした距離は一覧の先頭ブロックにまとめて固定され、
  カード右上にピンのアイコンが付きます
- 非表示にすると画面下部に「元に戻す」付きの通知が出るので、間違えてもその場で戻せます
  （編集モーダルを開き直す必要はありません）
- 開いたカードは、そのカードや画面の他の場所をタップすると閉じます
- 縦方向に動かしたときは通常のスクロールとして扱われ、スワイプは発動しません

スワイプが使えない環境（キーボード操作など）向けに、同じ操作は編集モーダルからも行えます
（チェックボックス＝表示/非表示、ピンのアイコン＝ピン留め）。

### 距離の追加・非表示

左上の編集アイコン（一覧の下の「距離を追加・編集」からも同じ画面が開きます）から
距離一覧を開けます。

- 上部の「よく使う距離」チップ（1マイル / 2km / 3km / 5km / 10km / ハーフ / フル）は
  ワンタップで出し入れできます。押すとその場でチェック状態が変わるので、追加できたかを
  下の一覧まで確かめに行く必要がありません。オフにしても削除ではなく非表示になります
- チェックを外すと、その距離はメイン画面から非表示になります（初期値の距離も含む）
- ピンのアイコンを押すと、その距離を一覧の先頭に固定できます
- 下部のフォームから任意の距離（メートル単位）を新規追加できます
- 追加した距離は右側のゴミ箱アイコンから削除できます

設定はブラウザの `localStorage` に保存されるため、サーバーやデータベースは不要です。同じブラウザで再訪問した際に設定が復元されます（別のブラウザ・端末には引き継がれません）。

### ダークモード / ライトモード

右上のアイコンでいつでも切り替えられます。初回はOSの設定（`prefers-color-scheme`）に従い、以降は選択したテーマが `localStorage` に保存されます。

### ホーム画面への追加・共有時のプレビュー

- `manifest.webmanifest` とアイコン一式により、iOS/Androidのホーム画面に追加した際にアプリらしいアイコンで表示されます
- SNSやチャットにURLを貼った際は、OGP画像（`icons/og-image.png`）付きのプレビューが表示されます

### km あたりのペース表示・直接入力

入力欄の上に「4'00" / km」のようなペースサマリーを常時表示します。いずれかの距離のタイムを入力すればここが自動更新されますが、逆にこのペース欄に直接「分」「秒」を入力しても、全距離のタイムがそのペースで計算されます。リセットすると `--'--"` に戻ります。

ヘッダーは画面上部に固定されており、スクロールしてこのペース欄が画面外へ出ると、
ヘッダー中央のタイトルが現在のペースに切り替わります。距離を増やして一覧が長くなっても、
下を見ている間に「いま何分何秒/kmの話をしているのか」を見失いません。タップすると
ペース欄まで戻ります。

### 使い方画面

入力ルール・カード操作・VDOTの読み方・保存されるものの説明は、フッターの折りたたみではなく
専用画面（`#help`）にまとめています。一覧の下の「使い方」ボタン、または
ポテンシャルタイムタブの「ポテンシャルタイムの読み方」から開けます。

### 初回だけ出る案内

説明文とバッジ（ログイン不要 / ホーム画面に追加OK / 瞬時に自動計算）、およびスワイプ操作の
ヒントは、初回訪問時だけ表示されます。✕で閉じられるほか、実際にペースを入力したり
スワイプ操作を使ったりした時点で自動的に消え、以降は表示されません（`localStorage` に記録）。
毎日使う人の一等地を、初回向けのコピーが恒久的に占有しないようにするためです。

### オフライン対応（Service Worker）

`service-worker.js` がアプリ本体（HTML/CSS/JS/アイコン）と、外部から読み込んでいる
Tailwind CDNのスクリプトをキャッシュします。一度開いておけば、電波の届かない場所
でもアプリを起動できます。ホーム画面に追加した状態での利用と特に相性が良い機能です。

### 距離カードの並び替え

各カード左上の「⠿」ハンドルを長押し（またはクリック）してドラッグすると、距離の
表示順を自由に入れ替えられます。並び順もブラウザの `localStorage` に保存されます。
非表示中の距離は編集モーダル内では距離の昇順で表示されます（並び替えの対象はメイン
画面に表示中の距離のみ）。ピン留め中の距離は常に一覧の先頭ブロックにまとまるため、
並び替えもピン留めブロックの内側／外側それぞれの中だけで行えます。

### VDOTトレーニングペース（お試し機能）

ペースサマリーの下にある「トレーニングペース」ボタンから専用画面（`#training`）を開くと、
直近のレース結果を元にJack Daniels方式のフィットネス指標「VDOT」と、5段階のトレーニング
ペースの目安を計算できます。使わなくてもメインのタイム換算機能には影響しません。

画面は「レース結果の入力 → VDOTとレベル」を上に固定し、その下を **練習ペース** と
**ポテンシャルタイム** の2タブに分けています。両方とも同じ入力から出る対等な結果なので、
縦に積むのではなく横に並べています（以前は1本の長い巻物で、ポテンシャルタイムが
上から800px下の折りたたみの中にあり、開くまで存在すら見えませんでした）。
タブバーはヘッダーの真下に貼り付くので、スクロールしても切り替えに手が届きます。

- 距離（1500m〜10000mのプリセットまたは自由入力）とタイムを入力すると、VDOTと各ゾーンのペース
  （分'秒"/km）がリアルタイムに更新されます
- 5ゾーン: **E/L**（イージー・LSD）、**M**（マラソン）、**T**（閾値走）、**I**（インターバル）、
  **R**（レペティション）。それぞれの名前をタップすると、「どれくらいの強度か」「どう練習に
  取り入れるか」の簡単なヒントが開きます
- 「VDOTとは？」をタップすると、VDOTという指標そのものの簡単な説明が開きます
- VDOTの数値の下に、初心者〜エリートまでのレベル目安をゲージバーで表示します（境界値は
  実際の計算式から逆算して検証済み。例: サブ4相当≈VDOT38、サブ3相当≈VDOT54）
- 「その他」で有効範囲（1,500m〜フルマラソン）外の距離を入力した場合は、計算結果が大きく
  外れうる旨の注記を数値のすぐ下に表示し、「エリート」等の断定的なレベル判定は出しません
- 画面を開くと ← ボタンへフォーカスが移り、タブは左右キーでも移動できます
  （入力欄へ自動でカーソルを移すと勝手にキーボードが開いて煩わしいため、あえてしていません）。
  VDOTの数値やレベル判定は更新されるたびに読み上げられます
- **ポテンシャルタイム**タブでは、同じVDOTで走った場合の他距離（1500m〜フルマラソン）の
  タイムを一覧で確認できます。短い距離の結果から長距離を計算した場合に「今すぐ出せるタイム」
  と誤解されないよう、「持久力トレーニングを積んだ場合のポテンシャルの目安」であることを
  タブの先頭に常設で明示しています。エンジン（VO2max）とスタミナ（脚作り）は別物であること、
  ポテンシャルに届かない場合はE/Tペースの練習で埋めていける旨は「ポテンシャルタイムの読み方」
  から使い方画面へ。有効範囲外（極端な短距離・ウルトラマラソン）には対応していない旨も
  注記しています
- メイン画面にレース結果を入力した状態でこの画面を開くと、上部に「メイン画面の ◯◯m を
  取り込む」ボタンが出ます。同じ数字を打ち直さずに済ませるためのもので、押したときだけ
  値が移ります（常時同期はしません。下記の通りレースペースと練習ペースは別物のため）
- 入力したレース結果はブラウザの `localStorage` に保存され、次にこの画面を開いたときに復元されます
- メインのペース相互換算機能（`currentPace`）とは完全に独立した別入力です。レースペースと
  トレーニングペースは別物のため、意図的に混ざらないようにしています

## 技術構成

- 静的HTML / CSS / JavaScript（ビルド不要、サーバー・データベース不要）
- スタイリングは [Tailwind CSS](https://tailwindcss.com/)（CDN経由、`darkMode: 'class'` でテーマ切り替えに対応）
- 距離設定（表示/非表示・ピン留め・並び順）とテーマ設定はブラウザの `localStorage` に保存
- オフライン対応は `service-worker.js`（Service Worker）で実現
- 依存パッケージなし

## ローカルでの確認

ビルド不要の静的サイトなので、`index.html` をブラウザで直接開くか、簡易サーバーで確認できます。

```bash
python3 -m http.server 8000
```

その後 `http://localhost:8000` を開いてください。

### キャッシュについて

`css/style.css` と `js/app.js` は `index.html` から `?v=N` 付きで読み込んでいます。
これらのファイルを更新してデプロイする際は、`index.html` 内の2箇所の `?v=N` を
インクリメントしてください。バージョンを変えないと、訪問者のブラウザ（や途中の
キャッシュ・プロキシ）が古いファイルを使い続け、変更が反映されないことがあります。

Service Worker（`service-worker.js`）でもオフライン用にファイルをキャッシュしている
ため、`index.html` / `css/style.css` / `js/app.js` のいずれかを更新したら、
`service-worker.js` 内の `CACHE_VERSION` と `PRECACHE_URLS` の `?v=N` も同じ番号に
合わせて更新してください。ここがズレると、Service Worker側だけ古いキャッシュを
配信し続けてしまいます。
